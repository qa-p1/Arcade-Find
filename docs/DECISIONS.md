# Decisions log

| Date | Decision | Why |
|---|---|---|
| 2026-10-09 | **Enter previews in Arcade Look** (`look.preview`); Shift+Enter opens with the default app; Ctrl+Enter reveals; Space (after moving into the list) also previews. If Look is missing, disabled, or doesn't accept the item, Enter falls back to the default app. | Owner request: previewing is the most common action and should be the default. The fallback keeps the primary key working without peers (NEW_APP_SPEC §2). |
| 2026-10-09 | **UI stack:** a software-rendered overlay (tiny-skia + cosmic-text) on a wlr-layer-shell surface (Wayland) or a winit + softbuffer window (X11, Windows, macOS); Settings is a separate egui/eframe process started on demand. | NEW_APP_SPEC §3 suggests Qt Quick for animated overlays and egui for compact utilities. The 1M-file index alone takes about 37–51 MiB, so a resident GPU or Qt context would break the "well under Look's ~75 MiB" target. Measured whole-app RSS: 52 MiB with 1M entries. Tradeoffs: no compositor blur from the app itself (Hyprland can blur the `arcade-find` layer), no animations, and square corners where the window can't be transparent (X11, macOS). |
| 2026-10-09 | **Default shortcut Ctrl+Alt+F**, verified against the family table (Box Ctrl+Alt+Space / Cmd+Shift+Space, Look Ctrl+Alt+Shift+Space, Lens Ctrl+Alt+Shift+L, Clipboard Ctrl+Shift+Space / Ctrl+Alt+V / Cmd+Shift+V, Wheel F8) by a unit test using Link's accelerator normalization. | Known overlaps outside the family: on Windows AltGr is Ctrl+Alt, so layouts where AltGr+F types a character (e.g. Czech, Hungarian) lose it while Find holds the shortcut; IntelliJ-based IDEs use Ctrl+Alt+F (Introduce Field); macOS VoiceOver uses Control+Option+F while it is on. Settings warns about desktop-owned shortcuts and about other Arcade apps (from the registry). |
| 2026-10-09 | **Rows:** up to 7 results the list grows; from 8 on it shows 5 rows and scrolls (both configurable). | The literal reading of "5 visible by default, stretching to 7 before scrolling". |
| 2026-10-09 | **Empty state:** at rest only the bar shows; Down on an empty query (or the "show recent on open" setting) shows pinned then recent items. | "At rest it is only the search bar" and "an empty query shows recent and pinned items" both hold. |
| 2026-10-09 | **Peer actions are generic:** any installed app's action that accepts every value of the selection is offered (actions without an array pattern only for one value); Look's preview is Find's own Quick Look; Box shows featured tools and pipelines. | New apps (e.g. Arcade Shelf) work without Find changes; nothing peer-specific to maintain. |
| 2026-10-09 | **`find.search` over Link has no frecency boosts, no recent items and no content search.** | Ranking must not reveal what the user opened (SPEC §10); file contents are read only when the user asks in Find's own window. |
| 2026-10-09 | **The overlay hides before a peer action only if the action opens UI** (`interactive` or `opens-ui`). | Look/Box windows need the screen; collecting into a peer (e.g. `shelf.add`) shouldn't close the search. |
| 2026-10-09 | **Search narrowing:** each keystroke re-checks only the previous query's matches and near-matches. | Keeps typing under 16 ms after the first letters at 1M entries; exact (tested against full searches). |
