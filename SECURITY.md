# Security policy

## Reporting

Report a vulnerability privately through GitHub's "Report a vulnerability" (Security tab of this repository), not in
a public issue. Expect an answer within a week. Fixes ship as a patch release through the normal rc → promote path. A
release found to be unsafe after it shipped gets the catalog's `bad` flag: Arcade Tools stops offering it and tells
installed copies to roll back.

## What Arcade Find guards, and how

Find indexes the **names, sizes and modification times** of the files under the folders you chose (your home folder by
default) and never reads a file's content, except for the optional content search described below. The index, your
settings, the files you opened (for ranking) and your pins stay in Find's own folders under your user account; Find
has no network code (no HTTP or TLS library is in its dependency tree, and neither Find nor Arcade Link opens a TCP or
UDP socket).

| Surface | Protection | Tested by |
|---|---|---|
| Files read | The crawler lists folders and reads each entry's name, size and modification time (`lstat`, so a symlink is recorded as a symlink and never followed). The default folder list leaves out `.git`, `node_modules`, `target`, caches, `/proc`, `/sys` and the Trash; network and FUSE-remote mounts (NFS, SMB, sshfs, rclone, …) are skipped unless the user turns that off. Changes are picked up by watching the indexed folders (inotify on Linux) and a periodic rescan. | `crates/find-core/src/scan.rs` (`crawl_reconcile_and_excludes`), `crates/find-core/src/mounts.rs` (`parses_mountinfo_and_flags_network`), `crates/find-core/src/exclude.rs` (`names_and_globs`, `paths_respect_opt_in_roots`) |
| Files stored | `index.bin` (names, sizes, times; no content) is written to a temporary file, flushed, renamed, and made readable only by the user (0600). It carries a CRC and format version: a file that is truncated, damaged or from another format is ignored and rebuilt by crawling, never repaired in place. `settings.json`, `frecency.json` (paths and open times, at most 2000, never content or queries) and `pins.json` are written atomically with mode 0600; a malformed `settings.json` is kept beside the new defaults. | `crates/find-core/src/persist.rs` (`roundtrip_and_corruption`, including the 0600 check), `crates/find-core/src/settings.rs` (`malformed_is_kept_and_defaults_used`), `crates/find-core/src/paths.rs` (`concurrent_atomic_writes_never_share_a_temporary_file`) |
| Content search | Only when you type a content query in Find's own window, and only if you installed ripgrep: Find never bundles or downloads it. It looks for `rg` in `PATH` and a few user install folders (`~/.cargo/bin`, `~/.local/bin`, `/usr/local/bin`, Homebrew, Scoop, WinGet, Arcade's shared `engines/bin`), runs `rg --version` and accepts it only if it answers "ripgrep 11" or newer, so anything you put in those folders under the name `rg` runs with that one flag. A search starts `rg` directly (no shell) with `--files-with-matches --fixed-strings --no-config --max-filesize 64M`, the pattern after `--`, results and time bounded, and kills it on cancel. Only matching file names come back; nothing from the files is kept. Another Arcade app cannot start a content search: `find.search` refuses one. | `crates/find-core/src/content.rs` (`builds_safe_arguments`, `finds_files_whose_name_has_a_newline`, `a_program_named_rg_that_is_not_ripgrep_is_not_used`, `honors_hidden_overrides_and_excluded_folders`, `cancel_still_works`), `crates/arcade-find/src/link.rs` (`search_results`) |
| File actions | Open and Reveal hand the path to the desktop (`xdg-open`-style handlers, the `org.freedesktop.FileManager1` D-Bus call, Explorer or Finder); the user chose the file. Rename stays in its folder, rejects separators and `.`/`..`, and never overwrites (`renameat2` with `RENAME_NOREPLACE`). Delete means "move to the Trash"; Find never deletes permanently. Copy puts text or a file list on the clipboard only when you ask; Find reads the clipboard only when you paste into its search box. | `crates/arcade-find/src/os.rs` (`names`, `rename_never_overwrites`, `uris_are_escaped`); moving to the Trash is not covered by a test |
| Link IPC | Arcade Link's sockets (0600, peer UID check, per-endpoint token). Find offers two actions: `find.search` (a name search of the index that returns paths, sizes and times, at most 1000 results, query at most 1024 bytes, never a content search) and `find.show` (opens Find's window). Turning "Connected apps" off stops Find's endpoint and removes its actions. When you pick an action for selected results, Find sends only those paths to the app you chose. | Link's own tests, `crates/arcade-find/src/link.rs` (`search_results`), `crates/arcade-find/tests/link_shelf.rs`, `crates/arcade-find/tests/hub.rs` |
| Instance socket | One resident instance per profile holds a lock, and a second launch (`--search`, `--toggle`, `--status`, `--quit`, …) talks to it over a local socket in the user's private runtime folder (0700, a symlink is refused) with a random 256-bit token kept in a 0600 file. A request is one JSON line of at most 64 KiB; a wrong token gets `denied`. | `crates/arcade-find/src/instance.rs` (`single_instance_roundtrip`), `crates/find-core/src/paths.rs` (`private_dirs_are_owner_only_and_never_symlinks`) |
| Child processes | Find starts only: its own executable (the Settings window `--settings-window`, the install dialog `--install-dialog`, a restart successor, which like a peer app starts through Link's `childenv::sanitize` so an AppImage mount is not inherited); ripgrep (above); `hyprctl` on Hyprland, to read and set Find's one key binding, with the program path single-quoted for the shell Hyprland runs it in; a peer Arcade app you open from Settings, at the path in its Link manifest; on Windows `explorer.exe /select`, the Inno uninstaller and `powershell.exe` (to write a shortcut, with the paths quoted); on macOS `open -R` and `defaults read`. No shell is started with user text. | `crates/arcade-find/src/hotkey.rs` (`hyprland::tests::quoting`), `crates/find-core/src/content.rs` (`builds_safe_arguments`); the other starts are not covered by a test |
| Settings export | The handoff Arcade Tools uses for backups is an allowlist (roots, excludes, pins, theme, shortcut and a few switches). It never contains the index, the files you opened, or login and peer state; paths under your home travel as `~/…` and a path that escapes it, or a platform-specific one, is refused. | `crates/arcade-find/src/portable_settings.rs` (`portable_roundtrip_excludes_local_state_and_rebases_home`, `validation_and_backup_leave_the_index_untouched`, `import_rejects_paths_that_escape_the_portable_home`) |
| Windows | Native windows only (the search overlay is drawn in software; Settings is an egui window in a separate process): no web view, no remote content and no scripts, so there is no Content-Security-Policy to bypass. Find opens a web page (its guide, release notes, licences) in your browser only when you click the link for it. | not covered by a test |
| Clipboard and screen | Find does not capture the screen. It writes the clipboard only on Copy, and reads it only when you paste into its search box. | not covered by a test |
| Logs and diagnostics | `events.log` records only "started" and "stopped" with a timestamp and version, 0600, rotated at 1 MiB. Stderr goes to a local `arcade-find.log` (Link rotates it); debug output exists only with `ARCADE_FIND_DEBUG` set. "Copy diagnostics" puts a header (versions, peers, index size, shortcut and tray state) on the clipboard and nothing else: no queries, file names or settings. Nothing is uploaded. | `crates/arcade-find/src/diagnostics.rs` (`rotating_the_event_log_leaves_the_stderr_log_alone`), `crates/arcade-find/src/settings_ui.rs` (`diagnostics_have_the_shared_header_and_no_paths`) |
| Crash reports | Find writes none: a crash (the release build aborts on panic) leaves only the local stderr log. Nothing is sent. | not covered by a test |
| Updates | Find is installed and updated by Arcade Tools, which trusts a release only through its signed `manifest.json` (see Arcade Tools' SECURITY.md). Find itself never downloads anything. | Arcade Tools' tests |

## Dependencies

`cargo deny check` (advisories, licences, bans, sources) runs in CI. Accepted advisories are listed with a reason in
`deny.toml` and in `docs/v1/DECISIONS.md` D18: none is a vulnerability Find can reach. The GTK 0.18 crates (RUSTSEC-2024-0429
in glib, RUSTSEC-2024-0370 proc-macro-error) come only from the `tray-icon` GTK backend, which Find uses on Windows and
macOS only, so no Find build compiles them. memmap2 0.8.0 (RUSTSEC-2026-0186) is used by xkbcommon only to map the
compositor's keymap, not through the affected `advise_range` and `flush_range` functions. The rest are "unmaintained"
notices (no known vulnerability) for chrono (the `trash` crate dates each file it moves to the Trash with it),
ttf-parser, and zvariant, zvariant_derive and zbus_names (merged into zbus 6;
Find's zbus, ksni, notify-rust and accesskit_unix are on zbus 5). The yanked async-executor and clipboard-win, and the
tokio and rustix advisories, were fixed by updating them.
Third-party licences are in `THIRD_PARTY_NOTICES.md` (`scripts/notices.py`; the Linux AppImage bundles no libraries,
which `scripts/notices.py --check-appimage` verifies in CI), shipped beside the program and shown from Settings.
